# ui-design-prompt

`ui-design-prompt[KD9DH]`

F: 让 AI 先确认风格、再直出可运行的界面设计
R:
A: `prompt.md`（提示词本体）；`tokens.md`（五组 token：颜色 / 字体 / 圆角 / 阴影 / 质感）
S: 风格未确认前不得开始设计；交付物是可运行 HTML/CSS 而非设计稿；图标必须内联 SVG，禁止字符 / emoji / CSS 圆圈充当图标

---

## 这是什么

把 UI 设计判断力固化成提示词。让 AI 不做"能跑但难看"的页面，直接产出视觉专业、层级清晰的界面。

## 什么时候用

- 从零生成界面：落地页 / Web 应用 / 移动端 / B 端后台
- 把已有界面改得更专业
- 统一项目的视觉风格与设计系统

**不适用**：只改逻辑或接口、不涉及视觉的开发。

## 去哪里用

`prompt.md` 与 `tokens.md` 一起注入（system prompt 或对话首条），再给设计需求。风格询问环节由提示词自带。

## 最不能违反什么

- **风格未确认，不动手**：先问清风格基调、场景、主色、明暗
- **token 不得临场编**：五组一律取自 `tokens.md`，同源，不得跨风格混用
- **菜单外风格先推导再确认**：按 `tokens.md` 第三节推导，摆给用户确认后才动手
- **交付物是代码，不是图**：单文件可运行 HTML/CSS
- **杜绝"原型感"**：图标必须内联 SVG、卡片必须有光影层次、禁止浑浊配色、图片必须真实、空状态必须有图形
- **改稿语义**："再好看一点" = 加留白与层级，**不换风格**；"换风格" = 只换视觉层，保留信息架构
