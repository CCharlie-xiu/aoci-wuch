# tokens.md

六种风格的 token 组。`prompt.md` 第 1 节选定风格后，**必须**从本文件取该风格的具体数值，不得临场编。

本文件四节：

```text
一 · 通用基础组       间距 / 断点 / 动效 / 无障碍 —— 所有风格共用，不随风格变
二 · 六风格 token 组   颜色组 / 字体组 / 圆角组 / 阴影组 —— 随风格切换
三 · 自定义风格怎么补   菜单外的风格，按同样四组推导 + 强制交用户确认
四 · 使用规则         取用顺序与禁止项
```

落地形态一律是 CSS 变量：写进 `:root`，全程只引用变量。

## 一 · 通用基础组（所有风格共用）

| 组 | 值 |
| --- | --- |
| **间距组** | 8pt 栅格：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96` |
| **断点组** | `375 / 768 / 1280` |
| **动效组** | 时长 `150–300ms`，缓动 `cubic-bezier(.4, 0, .2, 1)` |
| **无障碍** | 正文对比度 ≥ 4.5:1；点击区 ≥ 44px；尊重 `prefers-reduced-motion` |
| **字号阶梯（全集）** | `12 / 14 / 16 / 20 / 24 / 32 / 40 / 56`，各风格从中取子集 |

```css
/* 通用基础组 —— 每个风格都带上这一段 */
:root{
  --s-1:4px;  --s-2:8px;  --s-3:12px; --s-4:16px; --s-5:24px;
  --s-6:32px; --s-7:48px; --s-8:64px; --s-9:96px;
  --bp-sm:375px; --bp-md:768px; --bp-lg:1280px;
  --dur-fast:150ms; --dur:200ms; --dur-slow:300ms;
  --ease:cubic-bezier(.4,0,.2,1);
}
```

> 以下每个风格只覆盖 **颜色组 / 字体组 / 圆角组 / 阴影组**。

## 三 · 自定义风格怎么补

### 触发条件

出现下列任一情况，进入本节流程：

- 用户描述的调性**无法直接映射**到第二节任何一款
- 用户说"我想要 XXX 那种感觉""参考某个站""要更 XX 一点"
- 用户给了品牌色，但没说风格

### 铁律：先归因，再推导；推导完必须交用户确认

**不得跳过确认直接开工。** 自定义风格是 AI 最自由、也最容易跑偏的环节，确认点必须显式存在。

### 步骤

**第 1 步 · 提取三个锚点**

从用户的描述里抽出这三项，抽不出来就追问：

| 锚点 | 取值 |
| --- | --- |
| **明暗基调** | 亮 / 暗 / 中间调 |
| **色彩性格** | 单色克制 / 冷色科技 / 暖色亲和 / 高饱和撞色 / 低对比奶油 |
| **形态性格** | 方角硬朗 / 中性 / 圆润 / 极柔拟物 |

**第 2 步 · 先找基底，别急着造新风格**

用三个锚点去第二节里找**最近的一款**当基底。多数需求是某款的变体，不是全新风格。

**第 3 步 · 判断是「变体」还是「新风格」**

| 情况 | 处理 |
| --- | --- |
| 只改颜色（锚点 1、2 变，3 不变） | **变体**：沿用基底风格的字体组 / 圆角组 / 阴影组，**只换颜色组** |
| 形态锚点也变了（改了两组以上） | **新风格**：四组全部重新推导 |

> 只换颜色就自称新风格，是换皮不是换风格——用户能看出来。

**第 4 步 · 按固定顺序推导四组**

```text
颜色组 → 圆角组 → 阴影组 → 字体组
```

顺序有依赖，不可打乱：颜色定调 → 圆角定形态 → **阴影必须匹配圆角**（方角配柔光会打架）→ 字体最后定，因为它要匹配前三者的气质。

### 推导规则

**颜色组**

- **底色**：按明暗基调。亮调取 `#F8F9FA` ~ `#FDFCFA`（不用纯白）；暗调取 `#0A0A0B` ~ `#16161A`
- **主色**：按色彩性格定色相后，**必须压明度与饱和度**。硬规则：HSL 下饱和度 `55–75%`、明度 `50–60%`。直接用高饱和原色（`#FF0000` / `#0000FF` 类）必土——唯一例外是 Bold 这类明确要高饱和的风格
- **文字色**：永远不用纯黑。**从底色的色相往同方向偏一点**——暖底配暖黑（`#3A2A22`），冷底配冷黑（`#111827`），绿底配墨绿
- **语义色**：成功 / 危险 / 警告一律**降饱和**到与主色同一明度档，不要直接抄框架默认的高饱和值

**圆角组**

- 先按形态性格定基数 `R`：

  | 形态 | R |
  | --- | --- |
  | 方角硬朗 | 2 |
  | 中性 | 8 |
  | 圆润 | 14 |
  | 极柔 | 20 |

- 按倍数展开：`xs=R×0.5 / sm=R×0.7 / md=R / lg=R×1.4 / xl=R×1.8 / full=999px`
- **一致性红线**：按钮圆角与输入框圆角之差 ≤ 2px

**阴影组**

- **由圆角决定**：圆角越大，阴影越柔。大圆角配硬阴影非常违和
- 三档：

  | 圆角 | 阴影形态 |
  | --- | --- |
  | `R ≤ 4`（方角） | 硬阴影，零模糊：`4px 4px 0 <深色>` |
  | `R 8–14`（中性） | 双层柔和：`0 1px 2px …, 0 4px 12px …` |
  | `R ≥ 18`（柔和） | 大范围低透明：`0 2px 4px …, 0 16px 40px …`，或双层反向（拟物） |

- 暗色底一律改用「`1px` 边框 + 极弱外发光」，不用投影

**字体组**

- **族**：中文场景**只用 PingFang SC 系**——中文可选字体极少且多数不合格，不要给中文配花体。想表达气质靠下面两条：
  - 要「人文 / 编辑」感 → 标题换衬线族：`"Songti SC", Georgia, serif`（英文可上 Playfair Display），正文仍用无衬线
  - 要「科技」感 → 英文上 Inter，数字用等宽（JetBrains Mono）；中文不动
  - 要「亲和」感 → **加大字重**（600/700），不换字体
- **阶梯**：从全集 `12/14/16/20/24/32/40/56` 里按信息密度取 6–7 级
  - 后台 / 工具（密度高）→ 取偏小、跳跃小的一组
  - 品牌 / 营销（密度低）→ 取跨度大的一组（**跳跃感就是张力**）
- **字重**：按形态性格
  - 克制 → `400/500/600`
  - 亲和 / 大胆 → `500/600/700` 或 `600/700/800`

### 反例（不要这么做）

- ❌ 用户说"高级感"，就丢一堆灰 → 高级感来自**留白比例 + 层级对比**，不是灰度
- ❌ 只换颜色组就说是新风格 → 字体和圆角没动，那只是换皮
- ❌ 四组各自独立挑 → 必须成套推导，**圆角与阴影尤其不能脱钩**
- ❌ 主色直接用原色 → 见上面「颜色组」的硬规则

### 确认模板（摆给用户看的格式）

```text
风格：<自命名>
基底：<最接近的菜单风格> + <改了哪几项>
颜色组：底 / 面 / 线 / 主文 / 次文 / 主色 / 强调 / 语义
字体组：族 / 阶梯 / 字重 / 行高 / 字距
圆角组：xs / sm / md / lg / xl / full
阴影组：<形态>
识别特征：<一句话，什么不能省>
```

用户确认后，按本文件第二节的格式**固化成一节写回**（新增风格按同样四组补齐，缺组视为未定义，不得交付）。

## 四 · 使用规则

1. **先选风格，再取 token**。风格未确认前不要动 token。
2. **取用顺序**：通用基础组 → 该风格四组 → 写进 `:root` → 之后所有样式只引用变量，**不得再出现字面色值**。
3. **跨风格不得混用**。例如不能把 Warm 的 `--r-xl:24px` 配 Dark Tech 的颜色组——识别特征来自四组的一致性。
4. **风格特征优先于通用审美**。若通用规则（如"卡片要有阴影"）与风格特征冲突，以风格特征为准，并在交付时说明。
5. **新增风格**：菜单内的按第二节格式补齐；菜单外的走第三节流程推导并交用户确认。**缺组视为未定义，不得交付。**
