# ui-design-prompt

`ui-design-prompt[KD9SH]`

F: 让 AI 先确认风格、再直出可运行的界面设计
R:
A: `prompt.md`（提示词本体，全文注入即可用）；`tokens.md`（六风格的颜色组 / 字体组 / 圆角组 / 阴影组）
S: 风格未确认前不得开始设计；交付物是可运行的 HTML/CSS 而非设计稿；质量红线不可协商

---

## 这是什么

一份把「UI 设计判断力」固化成提示词的能力。

让 AI 不做"能跑但难看"的页面，而是直接产出视觉专业、层级清晰、可直接展示的界面。

## 什么时候用

- 从零生成一个界面：落地页 / Web 应用 / 移动端 App / B 端后台
- 把已有界面改得更专业、更好看
- 为一个项目统一视觉风格与设计系统

**不适用**：只改逻辑或接口、不涉及视觉的纯功能开发。

## 去哪里用

把 `prompt.md` 全文作为前置指令注入（system prompt 或对话首条），再给出具体设计需求。

风格询问环节由提示词自带，调用方不需要额外补充。

风格选定后，从 `tokens.md` 取该风格的**颜色组 / 字体组 / 圆角组 / 阴影组**——这两个文件要一起注入。

## 最不能违反什么

- **风格未确认，不动手**：必须先问清风格基调、场景、主色、明暗
- **token 不得临场编**：颜色 / 字体 / 圆角 / 阴影四组一律取自 `tokens.md` 的对应风格，四组必须同源，不得跨风格混用
- **菜单外的风格，先推导再确认**：不得自由发挥；按 `tokens.md` 第三节推导四组，摆给用户确认后才动手
- **交付物是代码，不是图**：默认产出单文件可运行 HTML/CSS
- **质量红线是硬约束**：纯黑纯白、emoji 当图标、魔数间距、无响应式等一律不合格
- **改稿语义要分清**："再好看一点" = 加留白与层级，**不换风格**；"换风格" = 只换视觉层，保留信息架构
