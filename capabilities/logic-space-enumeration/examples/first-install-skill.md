# 案例：用户首次安装后是否会自动安装其他 skills

## 分析问题

用户首次安装本仓库时，是否会立即触发 skill 安装，尤其是安装后自动再安装其他 skills？

## 分析范围与假设

- 检查仓库自身的文件、说明和可见自动化入口。
- 区分用户主动调用外部 skill 安装器，与仓库安装后自行启动另一个安装流程。
- “普通 clone”指仅执行仓库克隆，没有额外运行用户级脚本、IDE 扩展或外部自动化。
- 外部安装器自身的行为不在本仓库边界内。

## 变量与状态

| 变量 | 状态/取值 | 影响 |
| --- | --- | --- |
| 安装动作 | 普通 clone / 外部 skill 安装器安装 | 决定是否有外部安装行为 |
| 执行主体 | Git 操作 / 外部安装器 / 本仓库指令 | 决定后续规则由谁控制 |
| 安装后行为 | 无后续动作 / 安装其他 skills / 后续任务命中能力 | 决定是否进入递归安装或能力读取路径 |

## 约束与证据

- 根目录 `SKILL.md` 定义能力库的调用入口：适用任务发生时先读远程能力索引，命中后再读对应能力；它没有要求安装其他 skills。
- 仓库说明把本地仓库描述为编辑工作区，并给出能力读取流程。
- 仓库内未发现负责启动 skill 安装的脚本、hook 或安装配置。
- 使用外部安装器时，安装器如何识别并安装根目录 `SKILL.md` 由外部工具决定，本案例不推断其具体行为。

## 场景推演

| 场景 | 路径与推演 | 分类 |
| --- | --- | --- |
| 仅普通 clone | Git 克隆只按本场景约定获取仓库文件；仓库自身没有后续安装入口 | `EXPECTED`：在“仅普通 clone”的明确边界内，没有触发 skill 安装的步骤 |
| 用户主动用外部 skill 安装器安装本仓库 | 安装路径由外部安装器发起；它是否把根目录 `SKILL.md` 注册为 skill，取决于该安装器 | `EXTERNAL`：需检查具体安装器契约 |
| 安装后自动再安装其他 skills | 在仓库控制范围内没有发现从首次安装通往另一个 skill 安装器的路径 | `NO_PATH`：结论限于仓库自身可见机制；外部安装器的递归行为仍属外部边界 |
| 后续任务可能复用能力库 | `SKILL.md` 定义了任务触发条件；命中后读取远程索引，选中能力后按需读对应文件 | `EXPECTED`：这是已定义的读取/复用路径，不是安装路径 |

## 结论

在仓库自身控制范围内，没有发现首次安装后自动安装其他 skills 的路径。若用户主动用外部安装器安装本仓库，根目录 skill 如何注册需要依据该安装器的规则判断。任务命中能力库后，已定义的后续动作是读取索引和能力内容，不是安装子 skill。

本案例是基于仓库文件的静态分析；未执行真实安装器。后续如需判断特定安装器，应把安装器名称/版本及其安装配置加入变量与证据，再分析外部路径。
