# roles-qa.md · 角色场景与模版问答

本文件是**角色场景区分**的正文。读完本技能后：需要向对方要信息时**发出**模版提问；看到对方按模版发来的内容时**按本技能协助回答**。

---

## 不变规则

1. **只有两种角色：开发者 / 使用者。**  
   运营、产品、老板、个人学习都归入「使用者」，只影响话术深浅，不新增第三种角色。
2. **双方互相协助。**  
   - 一人可同时兼两角（先声明当前以哪角发言）。  
   - 也可多人分角。  
   - AI 始终按「当前发言角色」选逻辑，不按人头数拆第三套流程。
3. **模版问答的时机**  
   - **发出提问**：AI（或当前角色）在阅读本技能后，用下方模版向另一角色索取信息。  
   - **协助回答**：另一侧（或同一人切角）在阅读本技能后，看到模版提问，按对应「答法要点」填空回复；AI 据此继续验收或解答。
4. **不要跳过模版直接猜业务目标**；缺信息就发模版，不编造「对方想看什么」。

---

## 角色职责（场景区分）

| 当前角色 | AI 主责 | 必须向另一方做什么 |
| --- | --- | --- |
| **开发者** | 协助验证：结果对不对、有没有效果（代码 / DebugView / 开关） | 用「开发者 → 使用者」模版，问清对方**现在看到什么**、**想实现什么** |
| **使用者** | 不清楚时解答：看哪一页、官方 vs 自定义、漏斗怎么配 | 涉及具体埋点/改代码时，用「使用者 → 开发者」模版说清目标；收到开发者提问时按答法填空 |

交叉协作简图：

```text
开发者：改/查代码 → 自测有无效果 → 发模版问使用者「看到什么 / 想要什么」
使用者：看控制台 / 提目标 → 发模版请开发者落地 → 按开发者模版回填见闻
AI：按当前角色选 verify / analysis，并用模版补齐缺口
```

---

## 模版 A · 开发者 → 使用者（读技能后发出）

用途：开发侧联调或改完埋点后，向使用者核对「后台所见」与「业务期望」。  
AI 在开发者场景下，验证告一段落或需求不清时，**原样或略改姓名后发出**下列提问。

```text
【GA 协作提问 · 开发者 → 使用者】
请按条回复（看不清就写「未打开 / 不确定」）：

1. 你现在打开的是哪个 GA 账号 / 属性？（站点或属性名即可）
2. 你主要在看哪一页？
   - [ ] 实时
   - [ ] 互动度 → 事件
   - [ ] DebugView
   - [ ] 探索 / 漏斗
   - [ ] 其他：________
3. 你此刻实际看到了什么？（有哪些事件名、大概有没有量、有无报错感）
4. 你希望最终实现什么？请用业务语言描述，例如：
   - 想证明「某某按钮点击」有数
   - 想看「打开站 → 登录 → 下单」哪一步掉得最多
   - 想区分渠道 / 套餐 / 功能使用
5. 成功时你觉得「算做好了」的标准是什么？（一句话）
6. 若已有约定事件名，请列出：官方名 / 自定义名（没有就写无）
```

### 使用者答法要点（读技能后看到提问时）

| 题号 | 怎么答 | AI 如何用答案 |
| --- | --- | --- |
| 1 | 属性名；不确定就说不确定 | 排除选错属性 |
| 2 | 勾选页面 | 选 `verify` 使用者节或 `analysis` |
| 3 | 如实写看见/没看见的事件名 | 对照开发 DebugView，判断「有没有效果」 |
| 4–5 | 业务目标与完成标准 | 映射到官方/自定义事件与漏斗步骤 |
| 6 | 已有名字就列出 | 禁止开发者与使用者各用一套同义异名 |

开发者收到回复后：AI 优先做 **对照验收**（代码侧是否打出对方关心的名），而不是继续堆新事件。

## 模版 B · 使用者 → 开发者（读技能后发出）

用途：使用者说不清技术细节、或需要改具体埋点时，向开发者说清「要什么」。  
AI 在使用者场景下，一旦涉及具体事件/参数/漏斗落地，**发出**下列提问（可请使用者填完转给开发，或同一人切到开发角自答）。

```text
【GA 协作提问 · 使用者 → 开发者】
请按条回复（技术项不会就写「需要你定」）：

1. 业务目标（一句话）：想证明 / 想优化什么？
2. 用户路径关键步骤（按顺序，3～7 步）：
   ① ____  ② ____  ③ ____  …
3. 每一步更想用：官方推荐事件 / 自定义事件 / 不确定（可逐步标注）
4. 必须能在报表里拆开的维度或参数（如渠道、套餐、功能名）：____
5. 验收时你希望在哪看结果？
   - [ ] 实时有数即可
   - [ ] 事件列表稳定出现
   - [ ] 漏斗探索能画出断点
6. 环境：测服可关 GA？正式是否必须开？是否需要 Debug 联调窗口？
7. 已知 Measurement ID 是否已有？（有则告知开发，勿写进公开文档）
```

### 开发者答法要点（读技能后看到提问时）

| 题号 | 怎么答 | AI 如何用答案 |
| --- | --- | --- |
| 1–2 | 确认路径，缺步就追问 | 生成漏斗步骤候选 |
| 3 | 查 `event-design.md`：能官方则官方 | 写入业务仓字典，不写进能力库机密 |
| 4 | 参数 key 稳定命名 + 提示登记自定义维度 | `analysis.md` |
| 5 | 对齐 `verify.md` 级别 L1/L2/L3 | 验收话术 |
| 6–7 | 开关与 G-ID 只留业务仓 | `setup.md` |

使用者收到开发回复后：AI 用 `analysis` / `verify` 使用者节带其看数，不代替改代码。

## 模版 C · 一人兼两角（读技能后自问自答）

同一人既改代码又看后台时，AI 仍只认两角，可连续发出「先填 A 的使用者侧 → 再切开发验收」，或：

```text
【GA 协作 · 兼角声明】
当前我以【开发者 / 使用者】身份发言。
另一角的信息如下（按模版 A 或 B 填空）：
…
请按该身份继续协助。
```

禁止把「兼角」当成第三角色另开流程。

---

## 模版 D · 使用者不清楚时的最短解答包（读技能后直接给）

当使用者角色提问但尚未到「具体改埋点」时，AI **先解答**，不够再发模版 B：

| 对方问 | 最短答 | 深读 |
| --- | --- | --- |
| 数在哪看 | 实时看此刻；互动度→事件看列表（官方和自定义都在这） | `analysis.md` |
| 自定义事件特殊吗 | 一样进事件列表；按参数拆要先登记自定义定义 | `analysis.md` |
| 漏斗怎么配 | 探索→漏斗探索，按路径逐步加事件名 | `analysis.md` |
| 为什么没数 | 先确认属性；再看实时；仍无则转开发并建议发模版 A/B | `method.md` 排障 |
| 官方和自定义怎么选 | 能映射官方就官方，否则自定义 snake_case | `event-design.md` |
| 怎么看某个用户 | 探索 → 模板库 → 用户探索；前提是已上报 user_id | `user-analysis.md` |
| 我们的事件叫什么 | 先看 报告 → 互动度 → 事件；完整清单发模版 E 问开发 | `code-map.md` |
| 本能力没写到的 | 先查官方再答，标注来源与日期 | `gap-protocol.md` |

## 模版 E · 使用者 → 开发者：索取事件清单

用途：使用者要知道「我们的事件都叫什么」「代码和后台怎么对上」。

```text
【GA 协作提问 · 使用者 → 开发者 · 事件清单】
请按表回复，每个已上报事件一行：

事件名 | 官方/自定义 | 触发时机（用户做了什么） | 参数 key | 参数是否已登记自定义维度 | 上线环境（测服/正式）

补充：
1. user_id 是否已上报？登录、登出各怎么处理？
2. 事件字典放在哪（文件路径或文档链接）？
3. 业务上需要、但清单里没有的事件，请标出。
```

### 开发者答法要点

| 题 | 怎么答 | AI 如何用答案 |
| --- | --- | --- |
| 表格 | 按 `code-map.md` 第 1 节命令从代码里列出，不凭记忆 | 填入字典，走对账三步 |
| 1 | 对照 `setup.md` 登录/登出表 | 判断用户探索能否看到 user_id |
| 2 | 给路径；没有就现建字典 | `code-map.md` 第 3 节格式 |
| 3 | 缺的事件走 `event-design.md` | 先官方后自定义 |

使用者先自查：报告 → 互动度 → 事件。列表是 GA 已收到的事件名；没出现不等于没埋（新事件可能晚几小时），所以仍要开发给完整清单。

---

## AI 执行清单（每次）

1. 判定当前发言是开发者还是使用者（不明则先问）。  
2. 开发者：验证有无效果 → 信息不足就**发出模版 A**。  
3. 使用者：先解答（模版 D）→ 涉及具体落地就**发出模版 B**；要事件名就**发模版 E**。  
4. 看到任一模版的填空回复：按「答法要点」推进，不重复盘问已答项。  
5. 验收标准仍落在 `verify.md`；事件边界仍落在 `event-design.md`。  
6. 本能力没覆盖的问题：走 `gap-protocol.md`，不凭记忆答。
