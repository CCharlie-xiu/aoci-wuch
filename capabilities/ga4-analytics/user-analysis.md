# user-analysis.md · 按用户筛选与看单个用户

链接与路径见 `index.md` 页面分工。核对日期 2026-10-27，来源标注在各节。

## 先分需求

| 想做什么 | 做法 | 节 |
| --- | --- | --- |
| 看某个用户做了什么 | 用户探索 | 1 |
| 看一类用户（已登录 / 某渠道 / 付费） | 比较、细分 | 2 |
| 按自己的属性拆分 | 登记自定义维度 | 3 |
| 要原始 user_id 做分析 | BigQuery 导出 | 4 |

## 前提（逐项过，缺一项后面都看不到）

| 前提 | 检查 | 来源 |
| --- | --- | --- |
| user_id 已上报 | 用 `config` 或 `set` 设置；不放用户属性、事件参数、自定义维度 | 官方 user-id 页 |
| 登出写 `null` | 不发 `""`、空格、字符串 `"null"` | 官方 user-id 页 |
| 报告身份 | 管理 → 数据展示 → 报告身份，选 Blended 或 Observed | 官方 user-id 页 |
| 数据保留期 | 管理 → 数据设置 → 数据保留；用户级数据可选 2 或 14 个月 | 官方数据保留页 |
| 角色 | 改保留期、报告身份需 Editor 及以上 | 官方数据保留页 |

## 1. 看单个用户：用户探索

路径：

```text
analytics.google.com → 选对属性
→ 探索 → 模板库（Template Gallery）→ User explorer
```

也可：在已有探索的图表里右键数据点 → View users，筛选条件会成为临时细分。

要点：

| 项 | 说明 |
| --- | --- |
| 行 | 每行一个用户，标识列为 Effective user ID |
| Effective user ID | 有 User ID 用 User ID，否则用 Device ID（网站为 client ID） |
| 默认 | 按会话数取前 10 位用户；可调行数、起始行、排序 |
| 筛选 | 可加维度或指标筛选，多条件为 AND |
| 看时间线 | 点某一行 → 查看获客方式、汇总指标、按日期分组的事件时间线 |
| 生成细分 | 时间线里选若干事件 → 右上角 Create Segment |
| 删除用户数据 | 右上角删除图标，**不可撤销**；需 Editor 及以上 |

## 2. 看一类用户：比较与细分

| 场景 | 做法 | 状态 |
| --- | --- | --- |
| 已登录 vs 未登录 | 官方示例：用维度 Signed in with user ID 建比较（标准报告）或细分（探索） | 菜单名未核实 |
| 深度分析 | 探索里建细分，拖到标签页设置使用 | 官方探索页 |
| 长期复用 | 管理 → 受众 | 未核实，走 `gap-protocol.md` |

限制（官方探索页）：每个探索最多 10 个细分，每个标签页最多 10 个筛选条件。

## 3. 按自己的属性拆分

- 业务属性（用户等级、是否付费、套餐）→ 登记自定义维度。路径与规则见 `analysis.md`。
- **不要**把 user_id、手机号、邮箱登记成自定义维度：取值过多，报表会把数据归入 `(other)`，还占配额。
- 属性值用分层标签，不用个人标识。

## 4. 要原始 user_id

| 位置 | 能否看到原始 user_id |
| --- | --- |
| 标准报告 | 否 |
| 大多数探索（自由格式等） | 否 |
| 用户探索 | 能，Effective user ID 列，仅已登录用户 |
| BigQuery 导出 | 能，字段 `user_id`（Client ID 为 `user_pseudo_id`） |

## 排查

| 现象 | 检查 | 依据 |
| --- | --- | --- |
| 用户探索看不到 user_id | 上报方式是否为 config/set；报告身份是否 Blended/Observed；是否登录后才发 | 官方 user-id 页 |
| 只看到 Device ID | 该用户没有上报 user_id，或在登录前的事件 | 官方用户探索页 |
| 查不到老数据 | 保留期过期；探索和漏斗受限，标准汇总报告不受影响 | 官方数据保留页 |
| 新数据没出现 | 等待；联调用 DebugView，不用探索验收 | `verify.md` |
| 数据少或被隐藏 | 数据阈值、抽样（超过 1000 万事件的查询可能抽样） | 官方探索页 |

未列出的现象走 `gap-protocol.md`。
