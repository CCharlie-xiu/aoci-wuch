# 访谈清单（生成前必齐）

向用户一次问清（已提供的跳过）：

| 字段 | 说明 |
| --- | --- |
| `name` | 小写连字符，≤64，= 目录名 |
| `display_name` | 市场中文名 |
| `display_name_en` | 市场英文名 |
| `description` | 祈使语态：做什么 + 什么时候用 + 中文触发词 |
| `description_zh` / `description_en` | 详情页短介绍 |
| `examples_zh` / `examples_en` | 各最多 3 条「试试这样用」 |
| `version` | 如 1.0.0 |
| `author` | 合作方 / 作者名 |
| 输入 | 用户通常提供什么 |
| 输出 | 交付什么 |
| 步骤 | 固定流程 3～10 步 |
| 边界 | 明确不做的事；何时必须停下来问人 |
| 脚本需求 | 是否有可复现 bash/python 逻辑 |

## 从长对话抽取时

1. 归纳「可重复步骤」与「一次性上下文」（后者不进 Skill）  
2. 把判断规则写成编号步骤，不要散文堆砌  
3. 超过 ~4000 tokens 的领域知识拆到 `references/`  
4. 密钥、内网 URL、真实用户数据一律剔除
