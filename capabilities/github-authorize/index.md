# github-authorize

> 认知前置：若尚未阅读本仓库外层的 `README.md` 与 `SKILL.md`，须优先阅读二者完成认知搭建，再读本文件。

github-authorize[OA8SH]

F: 为指定 GitHub 应用执行用户授权流程
R:
A: 启动授权流程、接收授权结果、确认授权状态
S: 授权确认必须由用户本人完成；一个应用的授权不会自动代表其他应用已授权

---

## 适用场景

某个应用（桌面软件 / CLI / MCP / 自研 Agent）**已经具备 GitHub 授权能力**，
但当前设备尚未为该应用建立授权。

本能力执行的是**授权协议本身**，不持有任何应用的身份。
「是哪个应用」由调用方提供 —— 即目标应用自己的 OAuth App（`client_id`）及其授权回调配置。
详见 `implementation.md`。

## 判断条件

**前置条件（不满足则本能力不适用）：**

- 当前应用已经具备 GitHub 授权入口，或拥有自己的 GitHub App / OAuth App 身份

**满足前置条件后，出现下列情况之一，进入授权检查：**

- 应用明确提示需要 GitHub 授权
- 当前 GitHub 凭据或授权状态无法满足当前操作

判断链：

```text
应用是否支持 GitHub
↓
├─ 否 → 本能力不适用，到此结束
└─ 是 → 是否已授权
        ├─ 是 → 直接使用，不必执行本能力
        └─ 否 → 执行 github-authorize
```

授权是「**某个具体应用**代表用户访问 GitHub」。
本能力无法凭空为一个应用创造 GitHub 集成 —— 因此前置条件不成立时，
不应把任何带「GitHub」字样的场景都往本能力上套。

## 执行流程

```text
发现需要授权
↓
打开该应用的 GitHub 授权页
↓
【人工确认点】用户登录 GitHub 并点击 Authorize
↓
接收授权结果
↓
确认授权状态 → 继续原任务
```

## 人工确认点

授权页上的 Authorize 只能由用户本人点击。

- AI 可以：打开授权页、把页面推到用户面前、说明本次授权请求了哪些权限
- AI 不得：代替用户登录、代替用户点击确认、把用户凭据填入授权页

## 验证方式

- 接收授权结果：应用收到授权回调
- 确认授权状态：重新查询该应用的授权状态
- 反向验证：执行一次需要授权的操作，确认不再失败

注意：「授权页已打开」不等于「已授权」。
必须通过授权结果或状态确认，不能凭页面已打开就判定成功。

## 边界

- **不保存凭据到能力仓库**；授权产生的运行时凭据仅由本机安全存储使用
- 不代替用户完成 Authorize 确认
- 不代表任何特定应用的身份 —— 应用身份由调用方提供
- 不假设授权流程：web / device 由目标应用决定，见 `implementation.md`
