# Playbook · 体验侧测试报告（环境无关）

按关卡执行。可用任意能读文件、写文件、跑 shell 的 Agent。  
每关结束可对用户说：【进度】Gx 完成 · 下一关 Gy。

## G0 收料

收集（能拿到多少拿多少，缺项标明「未核实」）：

1. 时间窗（如「近两天」→ 具体日期）
2. 项目路径 / 分支名
3. 项目变更日志（如 `neverfogetlog.md`）关键条目——只取 change/config/url，不当缺陷台账
4. `git log --since=...` 与关键 diff 摘要
5. 近期对话已确认的产品语义

产出：改动点草稿（日期 · 模块 · 一句话）。

## G1 用户侧变化 + 代码对照（双栏）

| 栏 | 写法 |
| --- | --- |
| 用户侧变化 | 用户看得见的变化；禁止堆字段名与错误码 |
| 代码 / 接口对照 | 文件/函数/接口码/请求字段/关键开关 |

纯样式也可写「仅 CSS，文案未改」。

## G2 用例三列（核心）

建议分组：新主流程（必测）→ 相关交互 → 真机专项 → 页面/文案/布局 → 回归。

**每一条必须三列：**

| 列 | 读者 | 写法 |
| --- | --- | --- |
| 怎么测 | 测试 | 操作步骤 |
| 怎样算过 | 测试 | 通过标准 |
| 代码期望 | 开发 | 接口 code/字段/step/函数/禁止行为 |

禁止：只有白话、或只有字段名。  
清单顶部写优先顺序（如先 1–5、10–12）。

## G3 主交付落盘（必须）

在项目根或用户指定目录写入两份（内容同源）：

```text
<slug>-test-report.md
<slug>-test-report.html
```

- Markdown：结构见 `report-shape.md`
- HTML：基于 `html-template.html` 填表；单文件、无外链依赖、深色可读

完成后告知用户**绝对路径**，并说明：用浏览器打开 HTML 即可转发/截图。

## G4 可选增强（有能力再用）

以下全部可选，**缺一不影响 G3 完成**：

| 环境能力 | 可做 |
| --- | --- |
| 旁路 Canvas / 预览面板 | 镜像同一内容，方便 IDE 内看 |
| 浏览器自动化 | 打开 HTML 截图，存同目录 `*-top.png` / `*-tests.png` |
| 本地 http.server | 仅当 `file://` 被禁时临时起服务，用完关掉 |

禁止：因某 IDE 无 Canvas 而拒绝交付；禁止把专有格式当唯一产物。

## G5 转发口径（可选）

测：按「怎么测 / 怎样算过」走；字段看「代码期望」。  
研：联调对照「代码期望」；用户侧以「怎样算过」为准。
